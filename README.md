# Agent Memories：直した口調を、次の会話へ

AIの下書きに「もっと落ち着いた口調で」と毎回頼んでいませんか。文体と修正1つを自分で保存し、次の依頼へ手動で貼り直す無料メモです。

## 無料で1回試す

空欄を埋めずに、まず下書き1本。次のメモは架空の完成例です。文体と修正指示、仮のテーマまで入っています。閲覧とコピーにGitHubアカウントは不要です。

```text
以下の文体メモと前回の修正指示を使って、投稿の下書きを1本作ってください。
今回は下書きだけを作り、公開や送信はしないでください。

基本トーン: 落ち着いた丁寧語。大げさにしない。
避けたい言葉: 革新的、最強、絶対、完全自動。
好きな構成: 具体的な困りごと → 今日できる小さな行動 → 手動であることの限界。
次回も残す指示: 冒頭を「AIを活用するなら」などの一般論から始めず、読者が繰り返している作業を1つ書く。
今回のテーマ: AIの下書きに毎回同じ口調の修正をしている人が、修正指示を1つメモに保存し、次の依頼へ貼り直す方法。
```

1. 上のメモを全文コピーします。
2. 普段のAIへそのまま貼ります。「今回のテーマ」は必要なときだけ公開してよい仮のテーマへ変えてください。
3. 下書き1本を読み、冒頭に読者が繰り返している作業が1つ書かれているかを確認します。

[記入済みの無料メモをテキストで開く](https://raw.githubusercontent.com/Miraigent/Miraigent-agent-memories-mcp-catalog/main/examples/creator-style-one-correction.txt)こともできます。内容は上のコピー欄と同じです。

確認した結果は「満たした／要修正／未確認」のいずれでも構いません。これは手動で指示を渡すお試しで、自動保存・永続記憶の機能ではありません。実際の個人情報・顧客情報・秘密値・非公開の会話や設定は入力しないでください。

文章を使う前に、[「手動」などの提供条件が変わっていないか見比べる例](./CREATOR_STYLE_MEMORY_BEFORE_AFTER_SAMPLE.md#keep-offer-conditions)も確認できます。最初のお試しで、この確認欄を埋める必要はありません。

試した後や手順に迷ったときは、[困ったところだけ1行送る](https://github.com/Miraigent/Miraigent-agent-memories-mcp-catalog/issues/new?template=creator_style_trial_report.md)こともできます。報告は任意で、効果の比較や全欄の記入は不要です。公開されるため、会話本文や実際の投稿文は書かないでください。送信にはGitHubアカウントが必要ですが、閲覧・コピー・手元での試用には不要です。

## まず1本で試すコピペブロック

Xやnoteで「AIに毎回同じ投稿スタイルを説明している」と感じた人は、まず次の4行だけを埋めてAIに貼ってください。

```text
基本トーン:
避けたい言葉:
好きな構成:
今回のテーマ:
```

貼る時の文:

```text
以下のスタイルメモを守って、投稿文を1つ作ってください。

基本トーン:
避けたい言葉:
好きな構成:
今回のテーマ:
```

下書きを読んだら、次回にも残す文体の指示を1つ、自分のメモへ保存します。4行とその指示を次の依頼時に手動で貼り直してください。自動保存・永続記憶ではありません。 次の会話へそのまま渡せる形が欲しい人は、[修正1つを持ち越す完成例](./ONE_CORRECTION_TRIAL.md#まず貼れる完成例)をコピーできます。

```text
用途:
次回も残す指示:
次の依頼に貼り直したか: はい / いいえ / まだ試していない
```

1本の試用だけでは修正削減の効果は未測定です。比較は必須ではありません。必要な時だけ[無料テンプレの比較手順](./FREE_CREATOR_STYLE_MEMORY_STARTER.md#修正数を比べたい時だけ任意)で条件をそろえ、直した文の数を数えます。0件と未測定は区別し、条件が違う・不明なら「比較しない」にします。

事実・安全性は文体と別に確認します。個人情報、顧客情報、秘密値、非公開の会話や創作設定は入力せず、公開してよい仮例で試してください。AIサービスの規約と入力の扱いも確認します。

[試用結果を送る公開Issue](https://github.com/Miraigent/Miraigent-agent-memories-mcp-catalog/issues/new?template=creator_style_trial_report.md)では、困った手順だけでも、確認した結果だけでも伝えられます。完成例・4行テンプレのどちらでも使えます。報告や比較は任意です。会話本文・実際の投稿文・非公開の情報は書かないでください。送信にはGitHubアカウントが必要ですが、無料メモの閲覧・コピー・手元での試用には不要です。

結果も伝える場合は、分かる行だけ手元に残し、当てはまるものを1つ選んでください。空欄は未回答で、未使用・0件・失敗とは扱いません。

```text
確認した段階: まだ作っていない / 作ったが未読 / 最初の1本を読んだ / 次の会話へ貼り直した後の1本を読んだ
選んだ1点の確認結果: 満たした / 要修正 / 未確認 / 指示を選んでいない
この無料メモを知った場所（任意）:
```

「満たした」はその段階の出力を読み、選んだ1点を確認した場合だけです。貼っただけ・作ったが未読なら「未確認」にします。まだ修正指示を選んでいなければ「指示を選んでいない」にします。最初の1本と貼り直した後を両方伝える場合は、欄を2つに分けます。1点を満たしても、修正数・作業時間の削減や自動記憶の証拠にはなりません。

無料は1用途の手動メモです。継続履歴、複数用途、連携、設定支援、優先配布はPro・契約者向け候補で、このテンプレでは未提供です。結果を見てから必要な拡張を選べます。

## Try with one draft

If you keep re-explaining your writing style to AI, try this before your next draft.

Fill only these four lines first:

```text
Base tone:
Words to avoid:
Favorite structure:
Today's topic:
```

Then paste this:

```text
Please write one draft using the style memory below.

Base tone:
Words to avoid:
Favorite structure:
Today's topic:
```

After reading the draft, save one style instruction in your own notes. Paste the four-field memo and that instruction into your next request manually. This is not automatic or permanent AI memory.

One draft does not establish fewer edits. A paired comparison is optional: keep the same AI, topic, request and length, change only the style memo, and use separate new chats. Count each sentence corrected for tone, wording or structure once. Check facts and safety separately.

Keep missing or invalid counts as unmeasured, not zero. If conditions differ or are unknown, do not compare. Only matched, measured pairs can be labeled fewer, same or more edits; one pair is not a general effectiveness claim.

Use public-safe examples, not private conversations, customer data or credentials. Check your AI service's input policy. Viewing and copying this template needs no GitHub account; submitting an issue does.

Free is one manual use case. Continuous history, multiple use cases, integrations, setup support and priority access are Pro/subscriber candidates, not supplied by this template.

## 法人で検討する方へ

この無料資料で確認できるのは、公開してよい仮例を使った手動の文体指示と、下書き1本の試用手順です。社内データの保護、権限管理、業務システム連携、導入後の効果を実証する資料ではありません。

最初の試用では配布テキストの仮テーマを変えずに使えます。実業務への適用判断とは分けてください。

再現を検討するときは、公開してよい仮のテーマ・選んだ修正指示・下書きの確認結果を組にして記録してください。確認結果は「満たした／要修正／未確認」で残せます。これは手順を確認するための記録で、導入効果やセキュリティ審査の証明ではありません。

AIが作った保存用カードも、担当者が元の明示指示と照合してから採用してください。採用した指示と確認結果は分けて記録します。カードの生成は業務上の承認や実行を代行するものではありません。配布テキストを使って確認した場合は、参照したファイルの版も一緒に残してください。 次の依頼へ指示を貼り直した事実と、その後の出力で指示を満たしたかは別々に記録してください。出力が未読なら「未確認」のまま残します。貼り直しだけで継続記憶や業務上の効果を実証したとは扱いません。

公開Issueへの試用報告は導入効果や安全性の確認、業務利用の承認、契約の申込みにはなりません。

文章の修正で提供条件が変わっていないかは、[元の条件と修正後の記述を見比べる架空例](./CREATOR_STYLE_MEMORY_BEFORE_AFTER_SAMPLE.md#keep-offer-conditions)で確認方法を読めます。業務利用の導入判断とは分けてください。

法人での試用条件として、実施日・利用したAIサービス名・表示されたモデル名も手元に記録できます。モデル名が表示されない場合は「不明」とし、推測で補わないでください。条件が違う試用の結果を、このメモだけの効果とは扱いません。

業務利用の検討には[Miraigentの公開リソース](https://miraigent.com/resources?utm_source=github&utm_medium=readme&utm_campaign=agent-memories-mcp-catalog)で提供範囲を確認し、必要に応じて[無料診断](https://miraigent.com/diagnosis?utm_source=github&utm_medium=readme&utm_campaign=agent-memories-mcp-catalog)で対象業務を整理してください。社内情報や顧客情報は公開Issueへ記載しないでください。
